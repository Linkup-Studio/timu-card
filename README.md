# timu-card（タイムカードアプリ）

従業員向けのシンプルなタイムカード。各自のスマホのブラウザで「出勤」「退勤」をタップして打刻する。

公開予定URL: https://linkup-studio.github.io/timu-card/

## 勤務ルール（仕様）

| 項目 | 内容 |
|---|---|
| 定時 | 8:00〜17:00 |
| 休憩 | 12:00〜13:00（1時間・実働から控除） |
| 早出 | 8:00より前の出勤分 |
| 残業 | 17:00以降の退勤分 |
| 丸め | 早出・残業とも 15分単位で**切り捨て**（打刻は実時刻を記録し、計算時に丸める） |
| 実働 | 退勤 − 出勤 − 休憩重なり分 |

計算例: 7:40出勤・17:50退勤 → 実働 9:10／早出 0:15／残業 0:45

## 機能

- 現在時刻の表示（リアルタイム）
- 名前登録（初回1回・端末に記憶、「変更」で変更可能）
- 出勤／退勤のワンタップ打刻（同日の二重打刻は防止）
- 本日の記録（出勤・退勤・実働・早出/残業）
- 打刻履歴（直近2週間・端末内）
- **ワンタイムQRゲート**: 会社に掲示したQRを読み取らないと打刻できない

## ワンタイムQRゲートの仕組み

「会社にいないと打刻できない」ようにするための仕組み。

1. 会社に置いた端末（古いスマホ・タブレット・PC）で `display.html` を開いておく
   → **60秒ごとに切り替わるQRコード**が表示され続ける（一度開けばオフラインでも動作）
2. 従業員はスマホのカメラでそのQRを読み取る → トークン付きURLでアプリが開く
3. アプリはトークンを検証（現在の60秒窓＋1つ前の窓のみ有効）
   → 合格すると**5分間だけ打刻ボタンが有効**になる
4. トークンはURLから即座に消されるため、ブックマークしても次回は使えない

- トークン: SHA-256(シークレット | 時刻窓) の先頭10文字。シークレットは `js/config.js`
- 注意: クライアント側検証のため、コードを解析できる人なら理論上突破可能。
  GAS連携時にサーバー側検証を追加して完全にする予定

## 構成

```
index.html        … 打刻画面（従業員用）
display.html      … ワンタイムQR表示画面（会社設置端末用）
css/style.css     … スタイル（スマホ最適化）
js/config.js      … 共有シークレット
js/token.js       … ワンタイムトークン生成・検証（純粋関数・テスト対象）
js/timecard.js    … 勤怠計算ロジック（純粋関数・テスト対象）
js/app.js         … UI制御・QRゲート・localStorage保存・GAS送信
js/qrcode.min.js  … QRコード生成ライブラリ（qrcode-generator, MIT）
test.js           … 計算・トークンのテスト（node test.js）
```

- データ保存: localStorage（端末ごと）
- フレームワークなしの静的サイト → GitHub Pagesでそのまま公開可能

## テスト

node test.js   # 28件の計算テスト

## 今後の予定（未実装）

1. **スプレッドシート連携**: Google Apps Script（GAS）のWeb Appを作成し、`js/app.js` 冒頭の `GAS_URL` に設定すると打刻がシートに送信される。送信失敗分は端末にキューされ次回再送（実装済みの仕組み）
2. **月次集計**: GASの時間主導トリガーで毎月1日に前月の就業時間（出勤日数・実働計・早出計・残業計）を「月次集計」シートへ自動出力
3. **QRトークンのサーバー側検証**: GAS側でもトークンを検証し、クライアント改ざんを無効化
4. **打刻ミスの修正**: スプレッドシート上で管理者が直接修正する運用

## 制約・前提

- 日をまたぐ勤務（夜勤）は非対応
- 1日1回の出勤・退勤のみ（中抜けは非対応）
- GAS未連携の間、データは各端末のlocalStorageのみに保存される
